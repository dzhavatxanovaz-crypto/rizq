# Документы сайта и приложения

## 1. Что должно быть (матрица)

| Документ / информация | Когда обязателен | Норма |
|---|---|---|
| Сведения о владельце сайта: наименование/ФИО, адрес, e-mail | Всегда для сайта | ст. 10 ч. 2 149-ФЗ |
| Реквизиты продавца/исполнителя (ФИО ИП, ОГРНИП, адрес), режим работы | Продажа товаров/услуг потребителям | ст. 9 ЗоЗПП, Правила продажи |
| Политика обработки ПД | Сбор любых ПД | ст. 18.1 152-ФЗ |
| Согласие на обработку ПД - отдельный документ | Сбор ПД на основании согласия | ст. 9 152-ФЗ (с 01.09.2025 - отдельно) |
| Согласие на получение рекламы | Рекламные рассылки, пуши, SMS | ст. 18 38-ФЗ |
| Cookie-баннер и политика cookies | Аналитика/пиксели, идентифицирующие пользователя | 152-ФЗ |
| Публичная оферта / договор | Продажа через сайт, платные услуги | ст. 435-438 ГК, ЗоЗПП |
| Пользовательское соглашение | Аккаунты, UGC, приложение, контент | ст. 437-438, 1286 ГК |
| Правила рекомендательных технологий | Если лента/подборки персонализированы по данным пользователя | ст. 10.2-2 149-ФЗ - проверить применимость |
| Возрастной знак | Информационная продукция для детей | 436-ФЗ (скилл `religioznyy-kontent`) |
| Порядок возврата | Дистанционная продажа | ст. 26.1 ЗоЗПП |

## 2. Публичная оферта (продажа/услуги)
Структура: дата редакции и адрес → термины → предмет → порядок акцепта (оплата/нажатие кнопки + галочка) → цена и оплата (НДС) → исполнение (доставка/доступ) → возврат и отказ → ответственность (без ограничений, запрещённых ЗоЗПП) → ПД (ссылка на политику; согласие - отдельно) → споры (претензия - по желанию потребителя, суд по его выбору) → изменение оферты (не меняет уже заключённые договоры) → реквизиты.
Для рассрочки RIZQ оферта не подходит как основной документ: договор рассрочки заключается индивидуально по конкретному товару - скилл `islamskaya-rassrochka`.

## 3. Пользовательское соглашение (приложение)
- Предмет: простая неисключительная лицензия на использование приложения и контента (ст. 1286 ГК), безвозмездно, территория, срок.
- Акцепт: начало использования/регистрация. Для существенных изменений - уведомление пользователя.
- Правила поведения и UGC: запрещённый контент (экстремизм, оскорбления, реклама без согласования), модерация, право удалить/заблокировать, порядок жалоб.
- Права на пользовательский контент: лицензия RIZQ на публикацию отзывов/вопросов, согласие на распространение ПД (ст. 10.1 152-ФЗ) - отдельно.
- Ограничение ответственности: допустимо для бесплатного сервиса и B2B, но не против императивных норм ЗоЗПП для платных услуг.
- Религиозный контент: дисклеймер, что материалы носят просветительский характер и не заменяют консультацию имама/учёного - не снимает ответственность за запрещённый контент.
- Дети: возраст использования, согласие родителей.
- Контакты для обращений.

## 4. Регистрация и аккаунты
- С 01.12.2023 владельцы сайтов и приложений обязаны авторизовать пользователей из РФ только способами, перечисленными в 149-ФЗ (российский номер телефона, Госуслуги/ЕСИА, Единая биометрическая система, иные по закону). Регистрация только по иностранной почте/соцсети - нарушение. Проверь актуальную редакцию.
- Удаление аккаунта и данных - по запросу (ст. 21 152-ФЗ).

## 5. Русский язык
Информация для потребителей - на русском языке (ст. 8 ЗоЗПП). С 2026 г. действуют усиленные требования об обязательном использовании русского языка в информации для потребителей и вывесках (поправки 2025 г. к закону о государственном языке - проверить даты и объём). Арабские тексты, термины («мурабаха», «садака») - допустимы с пояснением на русском.

## 6. Магазины приложений
Если приложение публикуется в RuStore/Google Play/App Store - их требования к политике конфиденциальности, удалению аккаунта, возрастному рейтингу и платежам. Ссылка на политику - работающая и публичная.

## 7. Проверка существующих документов в репозитории
1. Найди: `privacy.html`, `rassrochka/soglasie.html`, футеры страниц, формы (`grep -rn "<form\|type=\"checkbox\"\|fetch(" --include=*.html`).
2. Сверь с фактической обработкой (скилл `personalnye-dannye`, раздел «Инвентаризация»).
3. Проверь: актуальная дата редакции, реквизиты, ссылки рабочие, галочки не проставлены, согласия отдельные.
4. Результат - таблица «документ | статус | проблема | правка | приоритет».

Правки в HTML можно сразу вносить в файлы проекта, сохраняя существующую вёрстку и стиль.
